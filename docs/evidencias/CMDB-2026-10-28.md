# Validación de la implementación CMDB

Fecha: 28 de octubre de 2026. Base Git:
`7255835b653ebd1b948d0c97a41cfffaacbb7a85`. La implementación está en el árbol
de trabajo posterior a ese commit, sin commit nuevo creado automáticamente.

## Entorno e independencia de datos

Servidor autorizado con Ubuntu 24.04.4, Docker 29.3.0 y Compose v5.1.1;
contenedores Python 3.12 y PostgreSQL 16. Aproximadamente 23 GiB de RAM total;
las mediciones son de esta máquina y ejecución, no garantías de rendimiento.

Se transfirió una copia de los archivos del proyecto excluyendo `.env`, secretos
y dependencias. Directorio remoto: `/home/servidor/catalogo-cmdb-validacion`.
Proyectos aislados: `catalogo-cmdb-tests` para pruebas y `catalogo-cmdb-app`
para aplicación/E2E, con volúmenes propios. No se modificaron las otras
aplicaciones del servidor. La API y frontend de evaluación se publicaron solo
en loopback, puertos 18000 y 15173; PostgreSQL de aplicación no se publicó.
Se utilizó el mismo patrón de override documentado en la
[línea base](BASE-PARCIAL-2026-10-28.md), con nombre `compose.validation.yaml`.

## Ejecución

```bash
docker compose -f compose.test.yaml -p catalogo-cmdb-tests run --build --rm backend-tests
bash scripts/verify_cmdb_persistence.sh
docker compose -f compose.yaml -f compose.validation.yaml -p catalogo-cmdb-app up --build -d
docker compose -f compose.yaml -f compose.validation.yaml -p catalogo-cmdb-app exec -T frontend npm run build
```

Las cuentas demo se generaron dentro del proyecto de aplicación y se guardaron
temporalmente en archivos remotos con permisos 600. El generador se ejecutó
con el ID real del usuario demo administrador:

```bash
docker compose -f compose.yaml -f compose.validation.yaml -p catalogo-cmdb-app exec -T backend python scripts/generate_cmdb.py --seed 202300582 --count 5000 --responsable-id ID_DEMO_ADMIN
docker run --rm --network host --env-file .e2e.env \
  -v "$PWD/frontend:/work" -w /work \
  mcr.microsoft.com/playwright:v1.63.0-noble \
  sh -c 'npm ci && npx playwright test --reporter=list'
```

En las repeticiones Playwright se reutilizó `npm ci` y se ejecutó solo
`npx playwright test --reporter=list`. No se publican los archivos de
credenciales ni las trazas de navegador, que pueden contener sesiones.

Se contrastaron 79 archivos de código/configuración entre el servidor evaluado

- La suite del backend combina seis unitarias con siete métodos de integración:
  el escenario P01–P11 del parcial y seis métodos específicos CMDB.
- El caso de generación inserta 5,000, repite con la misma semilla y comprueba
  cero nuevos, 5,000 únicos y 5,000 actualizados. Comprueba IP opcional en 1,666.
- Se verifican páginas y filtros, detalle, permisos efectivos, claves duplicadas,
  referencias inexistentes, mantenimiento de atributos originales y bitácora.
- Se rechazan ciclos de clasificación, dependencia mixta y autorrelaciones;
  se permiten conexiones cíclicas y se rechazan duplicados inversos.
- Se verifica una ruta de impacto y el límite con truncamiento explícito.
- Dos reparentados simultáneos incompatibles producen solo un éxito.
- La persistencia compara conteos y un checksum de atributos antes y después
  del reinicio. El entorno de integración contiene 5,001 dispositivos totales:
  los 5,000 sintéticos activos y un equipo manual desactivado por su prueba.
  Hay 47 servicios porque el escenario del parcial agrega un servicio válido
  adicional a los 46 importados; no es un cambio al control de importación.

## Incidencias reales

1. Una compilación se intentó mientras el frontend todavía ejecutaba su primer
   `npm install`; terminó con código 127 (`vite: not found`). Se esperó la
   disponibilidad real de Vite y se repitió satisfactoriamente. No se cambió
   el código de la aplicación para ocultar este fallo de preparación.
2. La primera suite de interfaz dio siete aprobados y un fallo: el localizador
   `getByLabel('Catálogo', {exact:true})` no seleccionaba el selector anidado
   en su etiqueta. Se inspeccionó el árbol accesible y se corrigió a
   `getByRole('combobox', {name:'Catálogo', exact:true})`, conservando el
   comportamiento que se verifica.
